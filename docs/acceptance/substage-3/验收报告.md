## 4. 本轮抓出并修掉的问题

### 🔴 bug #1（真 bug，本阶段引入的）—— 下载归属取错 webContents，A2 的下载被记成 A1

**现象**：第一轮跑完，同一个项目目录下两个文件的记录里 `agentId` **都是 A1 的**（`wb3-A2.txt` 被记成 A1，而不是 A2）。

**根因**：老规则是"一个智能体一个分区"，所以

```ts
ses.on('will-download', (_e, item) => { … ownerAgentOf(contents.id) })   // ← 闭包里的 contents
```

里的 `contents` 恰好就是"那一只"。改成按项目之后，**同一个 session 被该项目的多个智能体共用**，而 `will-download` 是挂在 **session** 上的 —— 闭包捕获的 `contents` 只是**第一个**创建这个 session 的页，于是同项目其他智能体的下载全记到那第一只头上。

**修法**：取回调的**第三个参数**（Electron 33 的签名就是 `(event, item, webContents)`，是真正发起这次下载的那个 guest）：

```ts
ses.on('will-download', (_event, item, fromWc) => {
  const owner = ownerAgentOf((fromWc ?? contents).id);   // ← 从 fromWc 取，不再用闭包的 contents
  …
});
```

修完复验：`wb3-A1.txt → agentId=107`、`wb3-A2.txt → agentId=108`，两条都 `agentSource=renderer`。

> **这个 bug 的意义超出本次验收：凡是"粒度变粗"的重构，都要重新检查所有"靠闭包/单例隐式绑定到旧粒度"的地方。**
> 这次是靠真机取证一眼看出来的（同一目录两个文件、agentId 却一样），只跑单测是发现不了的。

### 🟡 取证口径 #1 —— `guest_state()` 的 `sid` 读错了层，7 处断言变成"永远 None"

`guest_state()` 返回 `{site:{name,cookie,local,sid,href,at}, cookie, local, href, t0}`，**`sid` 在 `site` 底下**。第一版 7 处都写成 `s.get('sid')` → 恒 `None` → 页面明明已经登录（`document.cookie` 与服务端日志都能证明），断言却报「没登录 / sid=None」。统一走新增的 `s_sid(s)`。

### 🟡 取证口径 #2 —— 登录态测试页登录后只 `render()`，站点侧永远收不到第二条请求

站点侧的证据是"**请求实际带了什么 Cookie**"。页面登录后只重绘的话，`/whoami/<name>` 就只有"登录前游客"一条，断言会报"站点侧没记录到这次登录"。改成 `location.reload()` 后，页面侧与服务端侧才是**同一次事实**。

### 🟡 取证口径 #3 —— "暂停"不允许在途那一步落地，导致假失败

见 4.3 的口径说明。已改为：观测窗内不再推进 + 上限（≤ 暂停前 +1）+ `phase=paused`。

### 🟡 取证口径 #4 —— 证据用了"早先那一刻的快照"，等于说半句真话

`site_who_b1` 是「B1 刚打开时」抓的 list 快照，只含"登录前游客"一条；而断言名却在声称「A1 与 B1 各有登录前后两条」。已改成在**断言处**重新从 `site_events()` 现读，并且**对称地**同时断言 A1 与 B1。

### 🔴 工具链缺陷 —— 中途异常会跳过清理，把测试账号留在活库里

**现象**：第三轮跑到 section 6 时 `Page.captureScreenshot` 超时（CDP 已知抖动）→ 抛异常 → 直接跳 `finally`，**section 9 的"删测试账号"整个被跳过** → user 22 连同它的项目/智能体/消息留在**活库**里 → 第四轮「测试账号是干净的」前提失败，整轮跑废（跑了 23 秒就退出）。

**三处修**：

1. **截图兜底**：`shot()` 改成只记录成功/失败、失败重试一次、拍前先 `sleep 0.8`，**绝不抛**。截图是辅助证据，不参与断言，更不该拖垮整轮验收。
2. **开跑前回收残留**：新增 `phone_hash_of()`（纯 Python 算 `HMAC-SHA256(PHONE_PEPPER 或 DATA_KEY, phone)`，与服务端 `crypto.ts` 同一套；密钥只进内存、不打印）+ `purge_leftovers()`，每轮开始先把同号残留整体删掉（**幂等**，干净时是空操作）。
3. **`finally` 里再回收一次**：清理不能只挂在"跑到底"那一条路径上。

**顺带加了一条自检**，保证回收逻辑本身是准的、不是对着空气删：
