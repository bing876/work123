## 修「空动作」死循环（提交 bf6ff39，已 push）

- **现象**：用户点「继续」后立刻又 paused，聊天两次出现「我不认识这个动作「空」」，右边已是百度首页。
- **链路**：`agent.ts` 循环里，服务端返回 `ask_user` → 客户端立刻 `emit({kind:'ask'})` +
  `phase('paused')` 并 `return 'ask_user'`（apps/desktop/electron/agent.ts:119-124）。

- **根因**：`apps/server/src/routes/agent.ts` 的 `sanitizeAction` 虽然不会执行空动作

  且模型确实会输出 `{"action":"空"}` 这种占位词（所以文案是「我不认识这个动作「空」」）。

  3. 两轮都空 → `ask_user('empty_action', ...)` 写清「模型给的是空动作，我没执行、也没推进任务」；

## 第 8 步修驾驶：视口外输入框 + 搜索 URL 兜底 + 调试区自动收起（提交 2e0ce6d，已 push）

- **现象**：确认「打开百度搜天气」后连续失败「找不到『百度搜索输入框』」；右栏窄、黄框调试区把网页压矮，
  搜索框经常整条在视口外；人手点「继续」仍失败。
- **根因**：
  1. 页面助手 `find()` 的所有候选都被 `visible()` 过滤，而且**只认文字/placeholder/选择器能对上的节点**；
     模型爱给「百度搜索输入框」这种**描述性 target**，一个都匹配不上 → `find` 返回 null →
     `typeInto` 直接报「没找到可输入的输入框」→ 循环连败两次转 ask_user。
  2. 失败后没有任何退路，只会再试同一个 type。
  3. 调试区（黄框）高度固定占位，把 `flex:1` 的 `.browserArea` 压矮 → 搜索框更容易落在视口外，形成恶性循环。
- **修法（4 个文件，+134/-11，**不动布局宽度**）**：
  - `apps/desktop/electron/driver.ts`：
    - PAGE_HELPERS 版本 4→5，新增 `findInput()`：文字对不上时**不再返回 null**，
      改为挑页面上真实的 `input/textarea/contenteditable`（**只要求"有尺寸"，不要求在视口内**），
      按「搜索语义(name/id/placeholder 含 search|query|wd|kw|q|搜) > 在视口内 > 面积大」排序取第一个；
    - 新增 `pick()`：按 target 字符串缓存命中的元素（`isConnected` 失效即重挑），
      保证同一轮 type 的「找框 / 读回 / 三种写入」盯的是**同一个**元素，否则读回校验会误判"没写进去"；
    - 新增 `findClickable()`：click 时文字对不上、且 target 明说「框/输入/input/textarea/搜索栏」才退回真实输入框
      （避免把「百度一下」这种按钮误当输入框）；
    - `typeInto` 的 4 处 `find` → `pick`；`clickTarget` 的 2 处 `find` → `findClickable`。
      （`scrollIntoView({block:'center'}) + focus` 本来就有，所以视口外的框会被拉进来再输入。）
  - `apps/desktop/electron/agent.ts`：`type` 失败且错误匹配 `NO_INPUT_FOUND`
    （`没找到可输入的输入框|找不到…输入框`）时，从 goal 抠出关键词（`searchKeyword`）→
    直接 `open_url https://www.baidu.com/s?wd=<kw>` 一步到位，**不再空 type 两次再放弃**；
